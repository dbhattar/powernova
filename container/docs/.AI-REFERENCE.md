# PowerNOVA Container - Quick Reference for AI Assistant

> **IMPORTANT**: This file contains key organizational principles and structure for this project. Reference this when making future changes.

## 🎯 Project Organization Rules

### ✅ DO - Directory Structure

```
container/
├── website/          # Website source files only
├── docker/           # ALL Docker-related files
├── scripts/          # ALL utility scripts
├── docs/             # ALL documentation (except README.md)
├── .github/          # GitHub workflows
└── README.md         # Quick reference ONLY (stays at root)
```

### ❌ DON'T

- ❌ Place Docker files (Dockerfile, docker-compose.yml, nginx.conf) at root
- ❌ Place documentation files at root (except README.md)
- ❌ Place scripts at root
- ❌ Mix different types of files in the same folder

## 📝 Documentation Placement

| File Type | Location | Reason |
|-----------|----------|--------|
| Quick reference | `README.md` (root) | First file users see |
| Detailed guides | `docs/*.md` | Organized, easy to find |
| Deployment docs | `docs/DEPLOYMENT.md` | Part of detailed docs |
| Version history | `docs/CHANGELOG.md` | Historical reference |
| Project structure | `docs/PROJECT-STRUCTURE.md` | Reference material |

## 🐳 Docker File Locations

| File | Location | Why |
|------|----------|-----|
| `Dockerfile` | `docker/Dockerfile` | Grouped with Docker files |
| `docker-compose.yml` | `docker/docker-compose.yml` | Grouped with Docker files |
| `nginx.conf` | `docker/nginx.conf` | Used by Dockerfile |
| `.dockerignore` | `docker/.dockerignore` | Docker build context |

### Docker File References

When editing files, use these paths:
- Dockerfile reference to nginx: `COPY docker/nginx.conf /etc/...`
- docker-compose context: `context: ..` (parent directory)
- docker-compose dockerfile: `dockerfile: docker/Dockerfile`
- Build command: `docker build -f docker/Dockerfile -t image .`

## 🛠️ Scripts Organization

| File | Location | Purpose |
|------|----------|---------|
| `docker-helper.sh` | `scripts/docker-helper.sh` | Docker management |
| Future scripts | `scripts/` | All utility scripts |

Script must detect project root:
```bash
SCRIPT_DIR="$( cd "$( dirname "${BASH_SOURCE[0]}" )" && pwd )"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"
```

## 📚 Documentation Guidelines

### README.md (Root)
- **Purpose**: Quick start guide
- **Content**: Essential commands, links to docs
- **Keep it**: Short, scannable, beginner-friendly
- **Link to**: Detailed docs in `docs/` folder

### docs/ Folder
- **Contains**: All detailed documentation
- **Naming**: Use UPPERCASE.md for major docs
- **Organization**: Group by topic if needed
- **Always update**: CHANGELOG.md for changes

## 🔄 When Adding New Files

### Adding Documentation
1. Create in `docs/` folder (not root)
2. Add link in `README.md` if important
3. Update `docs/CHANGELOG.md`

### Adding Docker Files
1. Place in `docker/` folder
2. Update references in other files
3. Update docker-compose.yml if needed

### Adding Scripts
1. Place in `scripts/` folder
2. Make executable: `chmod +x scripts/script-name.sh`
3. Document in README.md or docs/

### Adding Services (Future)
1. Create service folder at root: `api/`, `database/`
2. Add Docker config in `docker/`
3. Update docker-compose.yml
4. Document in `docs/`

## 🎨 File Naming Conventions

| Type | Convention | Example |
|------|------------|---------|
| Major docs | UPPERCASE.md | `DEPLOYMENT.md` |
| Guides | kebab-case.md | `api-guide.md` |
| Scripts | kebab-case.sh | `docker-helper.sh` |
| Folders | lowercase | `docker/`, `scripts/`, `docs/` |

## 🚀 Common Commands Reference

### From Project Root

```bash
# Build with docker-compose
cd docker && docker-compose up -d

# Build with helper script
./scripts/docker-helper.sh build

# Build with Docker directly
docker build -f docker/Dockerfile -t powernova-website .

# Azure deployment
az acr build --registry $ACR --image app:latest --file docker/Dockerfile .
```

## 🔍 Quick Lookup

### Where is...?

- **Dockerfile**: `docker/Dockerfile`
- **docker-compose.yml**: `docker/docker-compose.yml`
- **nginx config**: `docker/nginx.conf`
- **Docker helper**: `scripts/docker-helper.sh`
- **Deployment guide**: `docs/DEPLOYMENT.md`
- **Version history**: `docs/CHANGELOG.md`
- **Quick reference**: `README.md` (root)

### How to...?

- **Build image**: `docker build -f docker/Dockerfile -t name .`
- **Run compose**: `cd docker && docker-compose up -d`
- **Use helper**: `./scripts/docker-helper.sh [command]`
- **Add docs**: Create in `docs/`, link in README.md
- **Update version**: Update `docs/CHANGELOG.md`

## 💡 Key Principles

1. **Separation of Concerns**: Each folder has one purpose
2. **Clean Root**: Only essential files at root level
3. **Centralized Docs**: All in `docs/` except README.md
4. **Logical Grouping**: Related files together
5. **Scalability**: Structure supports future growth
